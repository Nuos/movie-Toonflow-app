# 剧本流程、项目显示与原有功能核查

日期：2026-09-24。对照基线：仓库初始提交 `e03cf590eb0cab63534a4040db9acb4ec95b42a6`（Toonflow 1.1.8）。

## 结论

原有主流程入口未被本地新增工具替换。确实发现模型迁移后的依赖缺失；项目显示不全则来自原版的固定三列布局。已修复这两项，并改善开始规划、错误反馈、菜单标识及剧本保存。

| 项目 | 核查结果与处理 |
|---|---|
| 剧本助手无法开始 | 原版附带的 MiniLM 文件在迁移后链接目标缺失。已从 Git 原始对象恢复全部 6 个文件，逐文件校验 Git hash。权重实际保存在用户指定根目录，项目内沿用符号链接，无重复下载。实测向量维度 384、数值有限、归一化正常。 |
| 辅助依赖阻塞主流程 | 向量模型异常时保留原文记忆、近期上下文和关键词检索；自动摘要异常时保留未总结原文。文本模型自身错误仍会明确提示，不会伪装成功。 |
| “开始”含义不明 | 改为“开始剧本规划”。点击先执行本地准备检查，显示章节数与事件分析状态，并询问集数、时长、范围、比例、风格、付费策略。此步骤不调用 AI、不改写已有创作成果、不提交媒体生成。 |
| 项目缺失 | 数据库与页面均为 5 个项目。原始 CSS `repeat(3,1fr)` 被长内容撑宽，后两列挤出可视区域；改为自适应网格、允许内容收缩和换行。已验证 680、1058、1440 像素宽度无项目横向溢出。增加总数和完整简介展开。 |
| 剧本改名保存 | 原版前端编辑时丢失 ID，后端按名称查找可能产生重复。现在保留 ID，按项目与 ID 更新，事务保存；仅保存故事骨架时也不会因缺少 script 数组而失败。 |
| 提示词矛盾 | 决策层提示词原先一处禁止读取章节事件，初始化又要求读取。现允许需求确认和章节校验时读取必要事件，具体创作仍交由原有执行层。 |

## 原有功能保留情况

- 原始前端路径集合全部保留；186 个原有路由、Agent、Socket 路由及供应商文件无缺失。清单见 `local/workflow-feature-audit.json`。
- 小说原文：导入、事件分析、查看、编辑入口正常。
- 剧本管理：新建、批量上传、选择、导出、提取资产入口正常；现有 13 集剧本和资产标签可读取。
- 角色／场景／道具、资产库、音频分类、导演计划、制作工作台及原有模型设置均仍存在。
- 原有主菜单和项目流程菜单补充可见文字与键盘操作；新增提示词、声音和运镜模块仍为附加入口。
- “基于小说剧本”的项目不展示小说原文／剧本规划入口，这是原版 `nodelOnly` 条件，不是本地开发删除；“基于小说原文”的项目展示这两个入口。
- 登录自动进入是已有的本机部署配置，原登录路由仍保留；未在本次调整身份验证或模型供应商配置。

# 原有功能兼容性回归核查

核查日期：2026-09-24。原版基线：`e03cf590eb0cab63534a4040db9acb4ec95b42a6`。本轮兼容性核查已完成；结论限于下述运行证据与明确边界，不表示所有外部供应商或所有可能分支都经过实测。

## 已确认并修复

### 原音频选择与绑定入口

数据库默认导出通过 `Object.assign` 将 Knex 复制到包装函数，遗漏不可枚举的 `transaction`。新增声音库逻辑在原音频资产列表和绑定入口使用该对象，导致新项目打开音频选择器时报 `db.transaction is not a function`。原有声音测试预先通过另一条入口导入了声音，未覆盖此场景。

现直接导出保留表名类型的原 Knex 对象。补充原音频选择器首次导入、原角色音频绑定及解绑的 HTTP 回归测试；修复前失败，修复后通过。原声音库文件校验、跨项目隔离、父子音色继承、单次及批量视频音频引用等原测试继续通过。视频推理使用模拟适配器。

### 数据库导出、导入与清空

原导入流程先删除所有表，再仅用 `initDB` 建立基础结构。隔离测试导入本项目刚导出的备份，实际返回 500，缺少 `o_agentDeploy.type` 字段；`o_assets.defaultVoice` 及新增运镜、提示词、声音库表也不在这份基础结构中。这是原维护流程未兼容迁移字段及新增模块结构的问题，不能将所有缺字段都归因于新增模块。

现导出在同一事务中读取所有表；导入保留已安装结构，先校验表和字段，再在事务中清除并恢复数据。失败时整体回滚，不再回传可能包含私密配置的 SQL。旧版完整备份可省略扩展表和新增可选字段，局部对象不能冒充完整备份。未知表或字段会明确拒绝，不静默丢失数据。

两个清空入口统一先在独立内存数据库准备原版默认数据，再事务替换正式库中的数据，保留当前表结构。这样既清除扩展记录，也不会因扩展初始化缓存已完成而在清空后找不到表。未对用户当前数据库实际执行导入或清空。

`tests/database-backup.integration.ts` 验证 33 张表完整往返、重复主键失败回滚、字段不兼容、局部备份拒绝、空表恢复、旧版备份、两个清空入口及清空后的扩展结构可用性。

### 新建、删除与原图片供应商

- 新项目的默认图片模型、视频模型、清晰度及模式只写在 Zod 校验器中，而原中间件没有回填解析结果，实际入库为 null。已在创建逻辑中落实原先声明的默认值，未改变其他接口的校验行为。
- 删除项目时，原逻辑不清理新模块的提示词方案、复现记录、运镜方案、切片草稿、切片及声音库映射。现在事务清理这些关联，并删除本项目的 UUID 复现归档；同时清理原角色音频关联及章节事件关联。测试确认其他项目数据和共享声音文件保持不变。
- 复现记录将所有参考数据按 Data URL 切分，遇到原供应商支持的纯 Base64 会得到 undefined 并失败。现同时支持两种形式，保持传给旧供应商的参数格式，校验值统一按真实字节计算。
- 自动建立 H3 图片基准曾扩散到其他供应商，导致历史图片文件丢失时，原来可以执行的单图及批量重新生成被阻断。现在只在实际选择 H3 配套模型时强制建立基准；仍保留 H3 已确认参考的读取与内容校验。
- 视频提示词生成曾读取未选择的历史分镜图，文字生成模式也会因旧图片文件缺失失败。现按实际参考选择记录校验值，空参考选择不读取未使用的图像；没有削弱已选择参考的校验。

### 删除操作的完整关联清理

`tests/original-deletion.integration.ts` 在独立副本中补充 15 组生命周期场景。修复前实际复现：批量/制作资产删除留下子素材，单次资产删除留下子素材历史图片，音频更新留下关联，分镜删除留下运镜方案、草稿、切片和复现记录，轨道/剧集删除留下视频或轨道。新增模块的记录残留属于兼容性缺口；子素材/视频历史遗漏、按轨道名称跨项目计数、删除中途无法回滚在原版代码中已有。

现三个资产删除入口共用事务清理；音频子项移除在同一更新事务内清理。处理子资产、历史图片、剧本/分镜关联、音频绑定、声音库映射、提示词方案、复现记录及未再使用的图片编辑流程。制作资产删除尊重传入的项目范围。删除声音库子项或改用上传声音时同步清除旧默认声线身份；替换子项仍保留有效的音频组绑定，普通元数据保存及规范 URL 保存不会误解除声音库映射。

单次/批量分镜删除、视频轨道删除和整集删除共用制作资源清理：分镜删除清理其运镜和复现记录；仅当轨道已没有分镜时移除轨道及视频历史；直接删轨道保留原分镜并解除轨道引用；删剧集清理全部所属轨道（含空轨道），保留项目共享资产。判断依据是实际 ID，不再按其他项目可能重名的轨道文本。

文件在数据库事务提交后清理；仍被其他记录或提示词基准引用的文件、共享内置声音、仍在使用的编辑流程予以保留。UUID 复现归档按模块目录删除。测试包括共享图片最后一个使用者删除、同轨道另一分镜存续、其他项目同名镜头、替换音频子项、规范路径兼容；通过 SQLite 失败触发器验证资产和分镜删除在中途出错时，原记录、扩展记录和文件均保留。

边界：文件系统删除在事务提交后执行，磁盘权限或 I/O 故障仍可能造成文件未清理并返回错误，不能声称数据库和文件系统具有跨系统原子性。此轮没有进行中的真实推理任务；删除与后台生成并发的生命周期已由后文专项补齐。项目整体删除对编辑流程的清理已由本轮专项补齐。

### 批量分镜、预览与生成链路

`tests/original-storyboards.integration.ts` 新增 8 组场景、12 个原接口运行验证。图片提供商为临时目录中的确定性脚本，保留原 AI 类、供应商沙箱、文件保存和复现记录链路；H3 路径也通过临时模拟供应商验证，未调用真实 H3/ComfyUI 服务。

### 生成期间的选择与取消响应

新增 `tests/original-generation-lifecycle.integration.ts`，通过本地供应商 Promise 闸门控制返回时机。在临时数据库中验证单张、批量生成期间切换所选图片，以及请求取消后的响应和图片状态。修复前两种生成都会覆盖新选择，单张取消后原请求超时；修复后四个场景均通过。

- 生成结束不再重新选择占位图片；批量队列开始执行时也不再覆盖后续选择。
- 单张生成被取消后明确返回 HTTP 409，避免请求悬挂。
- 批量队列跳过已删除或非生成中的记录；后台发现记录已删除时直接结束，不再重复发送已返回的 HTTP 响应。

后续补查确认旧逻辑先保存图片和复现归档、再检查取消／删除，会残留文件。现在单张和批量资产图片使用同一事务检查任务仍处于生成中、资产仍属于当前项目，然后保存图片、复现结果和图片记录。任务已取消或目标已删除时丢弃本次复现记录与请求归档，不落盘生成结果。视觉基准更新沿用同一事务，避免删除后重建基准；取消入口只更新生成中记录，迟到的取消不会覆盖成功状态。

专项测试已扩展为普通供应商和 H3 两套本地适配器、单张／批量两种入口、切换选择／取消／删除三种时序，共 12 个场景。等待实际保存方法退出后检查数据库、旧路径和规范路径图片文件、请求归档以及视觉基准；正常结果字节与复现状态也有断言。修复前后证据为 `lifecycle-cleanup-before.log`、`lifecycle-cleanup-after.log`。31 组套件通过后，针对最终增强的 12 场景再次专项验证通过，类型检查和构建通过。

供应商计算本身并未中止，本次修复保证结果接收与清理。原分镜图片的删除与重叠请求行为已由后文专项补齐；各入口的验证范围分别列明。

### 衍生素材的生成生命周期

衍生素材入口原先不检查取消状态，供应商返回后仍写图片并改为已完成；删除途中还会留下结果文件和非 H3 复现归档。已复用资产图片的事务保存，生成前及文本提示词返回后检查占位记录仍处于生成中，避免文本阶段取消后继续出图。文本提示词仅在该任务仍被选中时写回资产，避免较旧任务覆盖后续任务的提示词。

`original-generation-lifecycle.integration.ts` 现包含 20 个场景：普通供应商与 H3、单张／批量／衍生三种入口、切换选择／取消／删除共 18 项；另有文本等待阶段取消或删除两项。后两项等待实际 Express 后台处理函数退出，断言未调用图片供应商、原提示词未被改写。复现记录、请求归档、原路径及规范路径文件均检查，失败前后日志为 `derivative-lifecycle-before.log`、`derivative-lifecycle-after.log`。原衍生素材成功、父图引用、文本失败、父图丢失及批内失败继续下一项测试同时通过。

### 真实 Socket 与决策／执行层联调

`tests/original-agent-socket.integration.ts` 在独立数据库中启动实际 Socket.IO 服务，用项目所附客户端经本机 WebSocket 连接原命名空间。使用实际决策层、执行层、工作区工具、ResTool 和记忆读写；仅文本模型被确定性流替代，图片／视频模型调用被明确禁止。23 个场景通过：

- 剧本助手 4 条执行分支、制作助手 7 条执行分支；决策层实际调用子执行工具，子执行层读取小说或通过 Socket 请求工作区数据并收到确认。检查思考配置和中断信号传递、分块 XML 原文、消息及内容块完成状态、记忆写入。
- 导演规划仍只开放原剧本读取工具，第二步关闭工具调用；没有被新增运镜／声音模块带入无关生成工具。
- 从 Socket 接收的故事骨架、策略、剧本文本经原 HTTP 保存接口写入并重新读取；另一集内容不变。这里解析客户端收到的 XML 再调用真实保存接口，不冒充浏览器编辑器的自动解析验证。
- 非法令牌断开、模型流创建失败、流内错误脱敏、停止并继续对话、断线中止模型、切换剧集停止旧任务并隔离新记忆。

复现并修复：断开监听原先挂在 Namespace 而非实际 Socket，导致断线不取消；停止被呈现为错误；制作助手流建立前异常仅写日志、流内异常直接回传原错误；切换上下文未中止旧任务；执行层返回后旧文本块未结束；思考增量发送字符串而非前端要求的对象。现均有运行断言。修改前后证据为 `agent-socket-before.log`、`agent-content-before.log`、`agent-socket-after.log`。最初测试对非法令牌连接事件轮询会错过瞬时连接，该测试观察方式已改为事件监听，不将它误报为服务问题。

上述证明实际编排与 Socket 协议在确定性文本响应下可运行，不等于真实模型每次都作出相同任务选择。前端未确认工具回调的中断／超时已由下述后续专项补齐；浏览器最终只读交互结果见文末；异常协议由隔离集成测试验证，未在真实项目人为注入错误。

### 工具确认等待的停止、断线与超时

后续真实 Socket 测试复现了两个助手在前端不返回确认时，停止与断线虽触发 AbortSignal，但工具 Promise 仍不结束。新增统一 `src/socket/request.ts`：停止或断线立即结束应用层等待；前端持续不确认时在 30 秒后报超时，并由 Socket.IO 自带机制清理传输层回调；迟到确认不再改变已结束的操作。停止／断线后的传输回调最迟仍在上述期限内释放，不声称立即移除所有底层回调。

剧本助手工作区读取，以及制作助手的读取、衍生资产通知、生成和分镜面板队列均使用该机制，并传递所属执行请求的中断信号。取消发生在排队期间时不会再发生成指令；已中止的新增／删除工具在进入数据库操作前拒绝执行。工作区思考消息也会结束等待。

`original-agent-socket.integration.ts` 扩充至 31 个场景：新增四个真实未确认工具的停止／断线案例，以及超时清理传输回调、迟到确认、预先中止不发请求、前端成功／错误四项协议测试。原工具套件新增队列中止与禁止写入断言，共 6 项。证据为 `agent-ack-before.log`、`agent-ack-after.log`、`agent-ack-tools-after.log`。超时专项将同一机制的等待时间缩短到 30～100 毫秒进行测试，正常运行默认仍为 30 秒。

### 视频生成中的删除与批量失败收尾

`tests/original-video-lifecycle.integration.ts` 用实际视频 AI 类和本地确定性供应商返回测试字节，验证两个原视频入口的成功、供应商失败、生成期间删除视频和删除轨道，以及批量首项参考图缺失而次项继续成功，共 9 个场景。它验证协议、状态和文件存储，不声称测试字节是实际可播放的模型视频。

修复前删除后仍写出结果文件；批量参考文件读取位于错误处理之外，首项失败会中断循环并留下生成中记录。现在视频保存使用同一数据库事务检查视频仍在生成、所属项目／剧本／轨道仍匹配，再保存文件及成功状态；记录已删除时不写文件。每个批量任务各自完成参考读取、生成及失败收尾，单项失败不阻断其他项。已完成视频的删除也改为事务清理记录和选中状态，再通过共用的引用检查清理文件；仍被其他视频引用时保留文件。正常生成用例同时验证共享文件保留及最后一个引用删除后的文件清理。当前 19 条轨道均有项目和剧本归属，未改变已有轨道结构。

修复前后证据：`video-lifecycle-before.log`、`video-lifecycle-after.log`；新增测试首次模拟供应商遗漏 inputValues 字段，该测试夹具已修正，并用修改前的本轮备份重跑，确认真实基线失败项为四个删除场景和批量缺参考场景。33 组回归通过后，最后补充的视频删除清理又通过视频专项和原工作台流程测试，证据包含 `video-workflows-after.log`。所有检查只操作临时数据库及测试目录，没有实际提交视频生成。

### 运镜片段生成／恢复期间删除分镜

在原 `camera-clips.integration.ts` 中新增两个受控并发场景：供应商返回前删除分镜；服务恢复读取已完成任务、等待视频下载时删除分镜。生成场景通过只读的本地协程状态等到后台工作退出，恢复场景等待实际列表请求完成，再断言片段记录、规范目录视频文件和请求归档均不存在。两个场景修复前均残留视频，修复后通过；其余分镜、轨道、原视频及提示词方案逐行快照保持一致。

生成与恢复共用事务提交结果：检查片段和所属分镜仍存在，再执行本地写入、非空校验及完成状态更新；网络生成／下载仍在事务外。已删除的请求不会重新落盘，收尾也会清除删除期间可能重新出现的请求目录。原片段幂等提交、参数／引用校验、正常失败、重启恢复和本地 MP4 服务读取测试同时通过。恢复测试仅模拟读取已有任务，断言没有发起新生成请求。日志为 `camera-lifecycle-before.log`、`camera-lifecycle-after.log`。

### 原分镜图片的重叠请求与旧结果收尾

新增 `tests/original-storyboard-lifecycle.integration.ts`，在普通供应商和 H3 两条实际适配链路下分别验证成功、失败保留旧图、生成中删除、手动换图、较新任务先成功后旧任务成功／失败、旧任务先返回、新任务失败后旧任务成功，共 16 个场景。修复前 14 个场景失败，修复后全部通过。通过实际 Express 后台处理函数退出确认任务结束，并检查记录、结果文件和复现请求归档；不以固定等待时间冒充完成。

分镜生成现在按当前单服务进程中的请求归属判定结果有效性，在本地事务中确认分镜仍属于原项目和剧本、仍在生成且请求仍最新，再写图片、复现结果与完成状态。过期请求丢弃自己的复现记录和归档；失败保留上一张图片，旧失败不覆盖新结果。单进程归属标记不声称支持多实例分布式部署，供应商计算本身也未被强制取消。证据为 `storyboard-lifecycle-before.log`、`storyboard-lifecycle-after.log`。

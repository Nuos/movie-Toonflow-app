# 人物定妆整合

入口：工作台侧栏 **人物定妆**，或 `/character-portrait.html`。

角色选择 → 填写简述 → DeepSeek 生成模板草稿 → 核对字段 → 保存版本 → 本地 Qwen 生成定妆照 → 人工逐项验收。在原素材页选择需要采用的候选图。新增页面出图不替换当前选图，也不删除历史图片。

## 同一模板与精确修改

源技能来自本机 `aigc-space /liyue-aigc/female-portrait-director`，固定副本位于 `data/skills/female-portrait-director`，附许可证与 `SOURCE.json`。保留原技能风格文件；整合使用独立四视图模式。

角色文档包含原始简述、明确设置、七个角色章节、八轴身份指纹、年龄性别、创作补全、负向约束、跨角色对照。所有写入必须经过同一个 Python 校验器和确定性编译器。未知字段、缺章节、无效设置、身高下限、明确设置与身份锚点冲突、章节数值与身高/比例冲突会报错。模板禁止角色章节另造布局。文字结构校验不等于模型必然画对，视觉验收仍需看图。

原始简述作为版本档案保留；编译后的图片提示词使用当前确认字段，避免旧简述中的配色等信息与已修改字段同时影响出图。未指定属性须列入创作补全。普通人工修改和 JSON 导入不调用文本模型。改变同一属性时须同步其明确设置、身份锚点及有关章节。

Agent 工具：

- `get_character_portraits`：读取当前项目角色、模板与版本。
- `save_character_portrait`：首次保存完整角色 JSON。
- `patch_character_portrait`：精确修改字段。`op=set` 替换一个字段；`op=append` 只追加给定原文，不要求模型复制旧文本。未指定字段由服务端保留。

HTTP 使用 `/api/characterPortrait/{create,list,get,draft,compile,save,patch,revision,generate,review}`。保存和补丁须带 `expectedRevision`，旧版本不能覆盖新版本。固定种子跨版本保留，可在页面明确改动。文档、模板版本、编译器哈希、最终请求、参考图哈希、模型、工作流和输出哈希进入版本或生成配方记录。

原单个/批量角色润色、衍生角色文本生成、明确角色类型的原生 AI 辅助，以及人物模板创建入口接入同一模板。场景、道具、分镜、视频和旧手写资产的原有入口保留；已建立结构化角色的自由文本改动须回到角色字段保存，不能绕过模板出图。原有入口中用户明确选定的图片供应商仍被保留，专用定妆页面默认本地 Qwen-Image-2.1。

## 图片尺寸与验收

默认本地 `comfyui-h3:qwen-image-2.1-quality`，50 步、固定种子，头像特写（28%宽）＋正面全身＋90°侧面＋背面，从左至右四栏。

- 定妆 2K：2048×1152，专用 `portrait-2k` 档。
- 定妆 1080p：交付1920×1080。Qwen 潜空间需要对齐尺寸，工作流使用1920×1088，固定裁去上下各4像素；不缩放、不放大。该处理在提示词、工作流和 profile 中明确记录。
- 原通用 Qwen 的 `2K`（2560×1440）与 `1K` 档不变。

默认沿用当前选中的角色图作为参考；API 可通过 `useReference:false` 从文字生成。参考内容与种子归档，后续在“提示词与图片复现”中按原工作流重放。存储中的完整配方支持追溯；像素级一致性需要同一模型文件和运行环境下实测，不能仅凭种子宣称完全复现。

成功返回图片后检查真实尺寸，状态为待视觉验收。七项人工检查为：四视图、同人同衣、角度与左右、全身无裁切、年龄体型、跨角色区分、文字开关。必须像素与全部视觉项通过才记为已验收。失败图片和历次验收保留。

参考图编辑时，若参考图哈希与同项目同角色的历史配方输出一致，系统逐字段比较旧模板与当前模板，把确切差异放在完整模板之前；追加操作只描述新增文字。差异清单、源配方与参考图哈希进入配方档案，无需 LLM 重写。未找到匹配来源时不推测原角色设定。

## 六种技法的标准化与使用要求

以下「来源名称」来自 [aoJK13tXJSY 的公开描述](https://www.youtube.com/shorts/aoJK13tXJSY)。**标准化分类、使用情境、必填条件与审计建议是本次设计建议，不是影片逐字内容，也未经本地生成验证。**

| 来源名称 | 建议分类与解读 | 适用情境建议 | 使用前应明确填写 | 审计重点 |
| --- | --- | --- | --- | --- |
| 荷兰角倾斜 | 构图／摄影机倾角；固定倾斜与随时间滚转应分成两种设定 | 失衡、压迫、心理不安 | 地平线倾斜方向与程度、起终姿态、主体位置；是否真的需要动态旋转 | 不能把倾斜构图直接当作运镜；若要求固定倾角，避免同时要求持续滚转 |
| 希区柯克 | 建议按常见用语映射「滑动变焦／dolly zoom」，但来源未展开定义，映射属编辑判读、待画面确认 | 惊觉、眩晕、心理冲击 | 摄影机前移或后退、相反方向的变焦、主体尺寸近似固定、具有前后景深度的场景 | 位移与变焦方向需相配；应同时检查主体比例与背景透视变化，不能用普通推镜充当完成 |
| FPV | 第一人称视角（First Person View）；是视点／摄影方式，不是唯一固定路径 | 身临其境、空间探索、快速穿越 | 起点、路径、通道、终点、速度、转弯方式、主体／视点归属 | 「FPV」本身不足以定义运动；若要求穿越，需有可通行空间；不能由名称推定必然俯冲或必须是真实无人机 |
| 摇臂拉升 | 升降／摇臂路径；拉升是否伴随后移、弧线或俯仰需要另定义 | 揭示环境、结尾扩展、人物与场景关系 | 起终高度、起终景别、主体锚点、是否后退／俯拍、要揭示的资讯 | 垂直升起与上仰摇摄不能互换；复合路径要可理解，不从名称擅自增加后拉 |
| 极速甩镜 | 快速水平或垂直摇摄；旋转运动与模糊过渡 | 快速转移注意力、动作衔接、转场 | 明确起终目标、方向、加速段、停稳段、模糊范围；若转场，写明下一画面关系 | 需落到可辨识终点；不能整段不可读；若只做一个连续镜头，避免同时要求不明确的场景切换 |
| 子弹时间 | 时间效果＋可选运镜；主体近乎冻结与镜头移动是独立设定 | 关键瞬间、动作高潮、戏剧性展示 | 冻结／慢动作的对象、镜头路径与弧度、粒子状态、起终构图、恢复正常时间的时点 | 普通环绕不等于子弹时间；需检查主体时间状态、空间结构与镜头移动是否连续；不能承诺模型精准实现 |

荷兰角、甩镜、滑动变焦、摇臂与主观视角的基本区别可对照 [Google 官方影片提示词指南](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/video-gen-prompt-guide)。该指南亦提醒，进阶角度或镜头效果的可靠程度可能不同。此处以官方定义协助标准化；并未用官方指南替 YouTube 影片补造示范内容。

## 建议的分类管理方式

不要把所有名称塞进单一「运镜」下拉选单。使用者应能先按叙事目的找方案，再看到实际会改动的镜头属性与使用条件。

| 分类维度 | 建议值或内容 | 管理目的 |
| --- | --- | --- |
| 物理／视觉机制 | 固定、摄影机位移、摄影机旋转、环绕、升降、光学变焦、焦点、构图／倾角、时间效果、虚拟路径 | 分清推近与变焦、摇摄与横移、倾角与旋转、子弹时间与环绕 |
| 叙事用途 | 观察、接近人物、揭示资讯、跟随动作、建立空间、突出线索、心理压迫、转场 | 让同一分镜有不同表达方案，保持剧情事实一致 |
| 主体与环境要求 | 主体锚点、动作、前后景深度、通行空间、遮挡物、背景稳定性 | 在生成前提示缺少的场景条件 |
| 运动要求 | 起终构图、路径、方向、速度、时长、停稳点、主体尺寸变化 | 把名称变成可执行的提示词内容 |
| 组合方式 | 单一机制、两种协同机制、分阶段机制 | 确保复合运镜有顺序与互相配合的参数 |
| 风险提示 | 几何变形、身份漂移、路径穿模、时间冻结失败、主体离画、终点不可读 | 帮使用者选择更适合当前素材的方案；不是模型通用能力排名 |
| 模型与素材条件 | 文字生成视频／图片生成视频／首尾帧、模型名称、实际选定参考图 | 明确提示词设计与实际生成输入的差别 |
| 来源与验证 | 原文名称、标准名称、作者、连结、日期、证据状态、映射理由、验证纪录 | 保持来源可追溯，让后续字幕或成片证据能补充同一条技能 |

「环绕」与「升降」可作便利的使用者分类，同时保存底层位移／旋转构成；分类不是互斥物理定律。FPV、倾角与时间效果可作可组合的附加设定，避免迫使用户把它们当成互斥路径。

每个技能建议至少提供：

- **名称与别名**：保留来源措辞，标记标准化是否已确认，例如「希区柯克 → 滑动变焦」仍需补片中证据。
- **适合什么情节**：以用户想传达的情绪或资讯描述，不只列摄影术语。
- **使用前提与必填项**：先检查素材与路径，再组装提示词。
- **首帧／尾帧构图与视频动态提示词**：图片写可见状态，视频写时间中的变化；尾帧文字不代表已经选定尾帧图片。
- **冲突与降级方案**：例如空间不足的环绕改为小幅弧移；无可靠深度的滑动变焦改为推近。这些是备选创作方案，不能宣称等价效果。
- **文字审计与成片审计**：前者检查要求完整与相容，后者另外检查实际画面；两者的通过状态独立。
- **来源证据**：显示「作者描述有此名称／字幕已核对／已看示范／本地已测试」，未取得证据的栏位留空并说明原因。

## 可实作的审计分层

1. **输入完整性**：主体、情节、首帧状态、主体动作、运动路径与结束状态是否足够；复合或高速运镜是否有可辨识终点。
2. **提示词一致性**：同时写固定与移动、推近与主体尺寸不变但未配变焦、冻结动作与正常快速行动等，应指出具体冲突句。
3. **素材相容性**：选用图片生成模式时是否真的选了图；首尾帧是否属于同一主体与可连接空间；文字审计无法检查图片内容时，显示尚待视觉确认。
4. **镜头连续性**：检查前后镜的方向、视线、位置、动作与叙事资讯；规则只能标记疑点，不能代替剪辑观看。
5. **生成后验收**：实际看片检查几何、身份、路径、终点、时间效果与可读性；本研究尚未执行，不能显示已通过。

对技能来源的评价与对用户当前提示词的评分也应分开：来源描述详细，不代表当前方案合适；文字审计得分高，也不代表已生成可用成片。

### 可供产品载入的来源索引

已建立 [camera-source-index.json](../../data/web/camera-source-index.json)，包含来源 URL、作者、证据说明与 40 笔 `index / timestamp / title / skillIds / notes`。40 笔 `skillIds` 均已对照实际技能 ID 填入；使用者可在技能库展开「按参考影片章节查找技能」，选来源、搜寻章节、定位技能或打开作者时间点。

来源索引的时间可换算秒数后附加 `&t=` 连到官方原片，例如 [00:48 章节](https://www.youtube.com/watch?v=VhTxVGw0Cms&t=48)。跳转连结只提供查阅位置，不代表本次已验证该时点的画面内容。技能卡来源也应保留精确原片 URL，不以频道首页代替。

## 3. 用六个主要技能组，外加修饰与配方

原来要求区分的五层保留；新增 Shorts 对应第六层「表演」。摄影库中每项技能只拥有一个主要组，另用标签描述用途和可组合性，避免同词重复建档。

| 主要技能组／稳定 ID | 回答的问题 | 典型技能 | 资料作用域 | 可用输出 |
|---|---|---|---|---|
| 景别与构图 `framing` | 这一刻画面要容纳什么？ | 大远景、全景、中景、近景、特写；双人构图、留白、框中框 | 单镜某时刻 | 分镜、首／尾帧、视频起止描述 |
| 机位与视角 `viewpoint` | 从哪个位置和方向看？观众代谁观看？ | 平视、俯视、仰视、顶视、倾斜；过肩、主观视角 | 单镜某时刻与空间关系 | 分镜、首／尾帧、视频 |
| 主运镜 `camera_motion` | 摄影机的位置或朝向如何随时间变？ | 固定、推、拉、横移、摇、俯仰、升降、弧移、环绕、滚转 | 单镜时间段 | 动态提示词；单帧只保留该时刻状态 |
| 光学与焦点 `optics_focus` | 视角、清晰对象和景深如何设定或变化？ | 焦距视觉意图、光学变焦、深／浅景深、固定焦点、跟焦、转焦 | 单帧状态或单镜时间段 | 静态状态进图像；变化进视频 |
| 剪辑与转场 `editing_transition` | 前后两镜如何连接？ | 切、动作匹配、视觉匹配、淡入淡出、叠化、遮挡切、甩摇衔接、J/L cut | 镜间边界，部分是段落 | 剪辑指令；具备相应能力时才编译多镜视频 |
| 表演与主体动作 `performance` | 人物或物件做了什么可见变化？ | 视线转移、呼吸、抿唇、吞咽、笑意收起、拿放道具、起身、行走 | 角色与单镜时间段 | 起始姿态进图像；动作节拍进视频 |

横跨这六组的**修饰项**：速度／缓急、幅度、稳定性、承载意图、画幅、时间处理（实时／慢动作）、光线／氛围、物理或虚拟视觉逻辑。它们不与主运镜互斥，不各自充当新的电影镜头数量。

**复合配方**另设 `recipes`：滑动变焦＝机位推拉＋反向焦距补偿；升高后拉＝垂直与纵深位移；跟拍反应＝主体行进＋相机相对跟随＋跟焦；甩摇转场＝前镜甩出＋切点＋后镜接入。配方引用原子技能，不复制其内容。

### 容易分错的名称

| 词汇 | 管理方式 |
|---|---|
| 推镜／zoom in | 必须选机位推近或固定机位变焦，不把中文「推」直接映射两者 |
| 拉焦 | 使用「转焦／rack focus」或「跟焦／follow focus」明确化；不是拉远镜头 |
| 跟拍 | 人与相机的相对关系／任务；路径可侧跟、后跟或前方迎拍。不要等同单一横移方向 |
| 360 度 | 要求使用者选「原地水平旋转」或「围绕主体移动」；前者 pan，后者 orbit |
| 手持／稳定器／无人机 | 稳定性或承载意图；不能单独决定摄影机路径 |
| 高机位／顶视／航拍 | 机位高度、朝向与承载需分开；顶视不等于一定有运动或无人机 |
| 倾斜构图／滚转 | 倾斜是某时刻的画框角度；滚转是该角度随时间变化 |
| 微距／大特写 | 前者属近距离成像意图，后者是画面尺度；不能只靠景别名称保证微距光学 |
| 一镜到底 | 镜头／剪辑结构；可以固定、移动或多阶段组合，并非一种独立路径 |
| 慢动作／缓推 | 动作时间处理与摄影机速度不同；不共用同一 speed 栏 |
| 悲伤／震惊 | 表演的意图，不是固定面部动作模板；需选可见动作及强度 |

## 4. 技能卡：使用情境、前置输入、限制与搭配

每张卡有「它改变什么」和「它不负责什么」的具体说明。下面是首批可编辑技能资料，不宣称已在特定模型成功生成。

| 技能 | 使用情境 | 最小前置输入 | 限制／风险 | 可组合技能 |
|---|---|---|---|---|
| 全景／建立构图 | 交代人物、出口、障碍及行走路线 | 角色位置、环境锚点、需入画物件、画幅 | 难读细微眼神；竖幅需重新检查边界 | 固定、拉远、升高、深景深、行走 |
| 中景／双人构图 | 对话、道具交接、身体反应 | 左右站位、双手与道具、视线目标 | 过浅景深可能让另一人或手部不可读 | 固定、轻跟、慢推、焦点转移 |
| 近景／特写 | 读脸部细节与决策 | 被观看部位、可见表演、起终状态 | 太近裁掉道具因果；不同面部部位未必同时清晰 | 固定、微幅推近、跟焦、克制表情 |
| 过肩 | 对话或观察对象的空间关系 | 前景肩膀所属者、被看对象、轴线侧 | 角色互换或肩膀突然消失；过肩不是景别 | 中景／近景、固定、反打剪接 |
| 主观视角 | 将观众置于人物观看位置 | 谁的视点、视线目标、可见肢体范围 | 不等于手持；显示角色完整正脸通常需另镜或反射依据 | 摇摄、跟随、呼吸晃动、视线匹配剪辑 |
| 低机位／仰视 | 看高度关系、人物与环境的压迫或开放感 | 相机高度、仰角、人物距离 | 情绪意义非固定；近距离面部比例会变 | 全景、弧移、升降、固定 |
| 固定观察 | 表演或事件本身构成变化 | 起始构图、主体动作、可读停留 | 锁定的是机位／朝向；人物仍可动，焦点仍可转 | 表演、转焦、环境动态、固定焦距 |
| 推／拉 | 接近细节或揭示处境 | 起幅／落幅、主体距离关系、停止条件 | 不是变焦；需要中途遮挡与比例检查 | 跟焦、表演、稳定支撑；反向 zoom 可组滑动变焦 |
| 横移 | 越过前景遮挡、建立层次 | 前中后景、方向、被揭示对象 | 新显露侧面缺参考会漂移；不应靠物件变透明揭示 | 固定焦距、转向补偿、主体行走 |
| 摇摄／俯仰 | 由目光或声音引向另一目标 | 起／终目标、原地机位、触发、方向 | 不能代替侧移或升降；注意空白行程 | 固定焦距、视线动作、揭示节拍 |
| 升降／摇臂 | 站起、越过障碍、局部到全局 | 起终高度、路径、落幅信息 | 升降与俯仰不同；不能仅由「组合」认定越轴 | 后拉、转向补偿、广景构图 |
| 弧移／环绕 | 看清侧面、关系重排、展示物件 | 中心对象、起终角度、空间锚点 | 需检查中途身份、背景、轴线；全周环绕风险较高 | 跟焦、稳定支撑、可见跨轴说明 |
| 固定机位变焦 | 位置不变时收紧或放宽既有信息 | 起终画框、焦距变化意图、固定视点 | 无法单凭变焦看到遮挡物背面 | 固定、表演；特殊配方中可与推拉组合 |
| 转焦 | 在同一构图内转交注意力 | from/to 对象、深度层、触发、终点停留 | 两对象需可见；首尾图的清晰目标要分开 | 固定或缓移、双人／道具构图 |
| 跟焦 | 维持移动人物或相机接近时的清晰 | 追踪对象、距离变化、清晰优先元素 | 不等于视线改变；单帧只保留清晰状态 | 推拉、跟拍、表演 |
| 滑动变焦 | 有意改变背景空间感而主体近似等大 | 反向焦距与距离趋势、主体锚点、起终背景 | 高复杂度；纯纵深组合不必然跨轴 | 主体站定、焦点追踪、克制反应 |
| 甩摇 | 快速转移注意或制作镜间衔接 | 起终对象、方向、结尾停稳；若转场再给相邻镜 | 单次甩摇不等于切镜；表情不能只在模糊段出现 | 快速节奏；两镜可组甩摇衔接 |
| 动作匹配切 | 保留同一动作的因果与连续 | 前镜结束／后镜开始动作状态、主体走向、道具手别 | 需要两个镜头；不能塞入单帧模型 | 多种机位、固定或跟拍、连续性审计 |
| J／L cut | 对话反应、声音先行或延续 | 两镜顺序、音源、音画各切点 | 需要音画剪辑或明确多镜能力；仅有视频提示词不保证执行 | 反应特写、过肩、环境声 |
| 视线／表情节拍 | 让人物看到、理解再作出反应 | 对象、触发、可见动作、强度、结果姿态 | 抽象情绪不保证表演；强度不要与剧情不符 | 中近景／近景、眼睛清晰、固定或慢推 |
| 虚拟穿越／变形 | 梦境、记忆、超现实连接 | 两端视觉锚点、转换逻辑、物件身份规则 | 明确 virtual/morph；不按实拍不可行直接封禁 | 选定运镜、形状匹配、独立转场配方 |

## 5. 面部表情：把新参考接入技能库

以下为本次原创表演技能示例，**不是 Shorts 的十种表情转录**。

| ID | 叙事意图 | 可见演绎 | 使用要求 | 常见风险 |
|---|---|---|---|---|
| `performance.recognition_hold` | 认出某人或信息 | 目光停在目标，眉间轻收，嘴唇微分后停住 | 近景或中近景；目标／反应先后清楚 | 直接夸张张嘴会改变情绪强度 |
| `performance.suppressed_grief` | 压住悲伤 | 下颚稍紧，吞咽，视线避开，重新看回 | 给足停留；脸和视线落点有交代 | 不应自动加泪或崩溃哭泣 |
| `performance.smile_fades` | 信任转为疑虑 | 笑意慢慢收起，嘴角放平，眼神重新聚焦 | 明确起始笑容与触发信息 | 一镜加入太多反复表情易不完整 |
| `performance.resolved_exhale` | 做出决定 | 短暂停顿，缓慢呼气，抬眼维持目光 | 终点反应可读；镜头不要高速越过 | 把心理决定写成空泛形容词 |

建议字段：`actorId / trigger / startState / visibleAction / intensity / endState / readableArea / holdIntent`。保留使用者情绪词作意图，再用动作落地；不要把某一面部肌肉变化宣称成唯一情绪诊断。

表演可与固定、推近或转焦组合。只有当表演与摄影机在时间、画框或焦点上冲突时才提示。例如人物的眼神转折若发生在相机快速甩过、脸已出框的阶段，应提示重新排序；不是看到「震惊＋甩摇」就一律封禁。

## 6. 管理规则与最小资料契约

分类是知识资料管理，不需要把每张卡都实作为新的 Agent SKILL.md。产品内技能卡可版本化；真正的 Agent 技能负责依这些资料编排、编译与审阅。

```ts
type SkillGroup =
  | 'framing' | 'viewpoint' | 'camera_motion'
  | 'optics_focus' | 'editing_transition' | 'performance';

type CameraSkill = {
  id: string;                  // 稳定，不随显示名称或翻译改变
  version: number;
  name: string;
  aliases: string[];           // 搜索用途；含有歧义的 alias 需先消歧
  group: SkillGroup;
  scope: 'frame' | 'shot' | 'shot_boundary' | 'sequence';
  summary: string;
  intents: string[];           // 揭示、反应、跟随、空间建立等，可多选
  useCases: string[];
  requiredInputs: { key: string; reason: string; severity: 'required' | 'recommended' }[];
  changes: string[];           // camera.position / orientation / focalLength / focus / subject.action / edit 等
  invariants: string[];
  compatibleWith: string[];    // 可组合不代表任意同时使用
  conflicts: { condition: string; reason: string; remedy: string }[];
  risks: string[];
  reviewChecks: { phase: 'plan' | 'image' | 'video' | 'edit'; evidence: string }[];
  outputs: ('storyboard' | 'image' | 'video' | 'edit')[];
  providerNotes: { provider: string; support: 'documented' | 'tested' | 'unknown'; note: string }[];
  sourceIds: string[];
  evidenceStatus: 'metadata_only' | 'source_read' | 'example_viewed' | 'locally_tested';
  lifecycle: 'draft' | 'active' | 'deprecated';
};

type SkillRecipe = {
  id: string;
  version: number;
  skillIds: string[];
  phases: { order: number; trigger?: string; skillIds: string[]; endpoint: string }[];
  priority: string[];          // 表演可读性、道具、构图、风格等优先顺序
  explanation: string;
};
```

前端筛选可按「技能组」「用途」「适用输出」「复杂度」「证据状态」并列；不要把某个用途当父分类后重复保存同一技能。譬如 arc 既可展示产品又可呈现人物关系，仍只有一份技能定义。既有 motion ID 保留兼容，可在 catalog 新增 group/subgroup/requirements，不必重命名历史方案。

用户可收藏卡片、复制成自定义版本、调整前置条件、停用或弃用；模板引用固定 `skillId + version`。更新公共卡片后，已采用提示词保持快照，显示「有新版本可比较」，不悄悄重写影片工程。

来源需记录 `url / author / checkedAt / evidenceStatus / supportedClaims`。观看某段作者视频只证明看到那段示例，不等于本机模型支援。没有观看的来源不可拥有 `example_viewed`，更不可标记 `locally_tested`。

## 7. 兼容规则：依控制量和时间判断

| 组合 | 预设判定 | 理由／处理 |
|---|---|---|
| 固定＋人物行走 | 合法 | 相机不动，人物可动 |
| 固定＋转焦 | 合法 | 焦点变化不要求机位改变 |
| 固定焦距＋推轨 | 合法 | 机位变化；主体大小可能变 |
| 固定机位＋变焦 | 合法 | 位置保持、焦距变化 |
| 严格锁定机位／朝向＋同时横移 | 冲突 | 同一时间控制量互斥；分阶段或删除约束 |
| 先固定、接信后横移 | 合法分阶段 | 有触发及顺序；不可用全段「完全固定」描述 |
| 后拉＋焦距变长＋主体近似等大 | 合法配方 | 滑动变焦；标高复杂度与成片待验证 |
| 视点固定的 zoom＋要求看见柱后新人物 | 风险提示 | 单纯放大不揭开遮挡；需改视点或交代人物走出 |
| 弧移跨轴＋连续可见跨越 | 可放行 | 有可理解的空间转换；仍需看片 |
| 大远景＋细微眼神 | 可读性风险 | 不直接否决创作；让用户确认信息是否真需读清 |
| 特写＋同时必须看见双手交接 | 画框需求冲突 | 重构景别或拆镜 |
| 转焦＋起始／终点引用同一清晰目标 | 目标不完整 | 分别输出首帧和尾帧的清晰对象 |
| 同镜甩摇＋自动添加 cut | 不允许自动推导 | 选了甩摇不表示同意切镜；转场需明确第二镜 |
| J cut＋只有单镜静态图 | 作用域不匹配 | 保留于剪辑计划，不发往图片提示词 |
| 手持呼吸＋完全无朝向扰动 | 条件冲突 | 选稳定观察，或改为站位固定但允许轻微扰动 |
| 虚拟穿物＋实体不可穿越 | 需声明视觉逻辑 | 允许 virtual，指定锚点；不靠物理不可行一概阻挡 |

规则结果应包含命中的字段、时间阶段、原因和可选修复。语义未知时输出「待人工核对」，不要从字符串不相等直接断定人物衣服或持物手违反连续性。时长建议是创作启发式，不宣称所有模型硬性要求至少某秒数。

## 8. 对现有 Toonflow 流程的落地建议

1. 在目前运镜候选卡加入「技能分类」「适用情境」「需要填写」「可搭配」「注意事项」「核查方法」折叠区。原生视频提示词入口不变。
2. 状态型技能更新起始／结束画面；动态技能更新视频过程；转场技能更新镜间边界。编译器禁止将多时段运动整串贴入单帧。
3. 表演独立编辑并被所有候选共用。同一分镜比较固定／推近／横移时，事件与角色表演保持一致；若某候选真的改变表演，明确显示差异。
4. 模板由原子技能组成，保留各技能用途与必要输入。多技能组合有清楚阶段和控制量，避免「任选多个术语直接拼接」。
5. 审计分「计划完整性」「图片可读性」「视频运动」「剪辑／音画」四相。没有实际素材就维持未评估，不让计划高分冒充成片验收。

### 可直接验证的产品案例

- 选「固定」仍可选表情、主体行走或转焦；不误报冲突。
- 选「微表情」后提示脸部可读区、焦点与停留；不自动把悲伤改成流泪。
- 选「主观视角」不自动加手持，选「顶视」不自动加无人机运动。
- 选「光学变焦」时清楚显示它改焦距；与推轨有独立的说明与核查。
- 选「甩摇」不增加镜头数；选「甩摇衔接」要求前后两镜及切点依据。
- 新视频来源若只有 oEmbed 元资料，显示「仅核实标题／作者」，不展示伪造逐镜示例。
- 采用新技能版本时让用户比较差异；原分镜、提示词与已生成资产不被资料库模板更新改写。

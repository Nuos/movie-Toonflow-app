# Toonflow 视频审计调研

日期：2026-09-27。范围：生成成片是否满足分镜、提示词、参考资产与声音要求。本文完成首轮资料研究与方案比较；随后已接入文件技术检测，尚未完成候选内容评估模型实测、准确率校准或自动内容放行。实验进度见 [校准记录](video-audit-calibration-20260927.md)。

## 1. 结论与依据边界

建议采用“技术测量 + 分项视觉核对 + 声音核对 + 人工复核”的组合方案。单个质量总分不足以证明一条成片可用。验收要求来自项目创作要求；评估方法参考公开研究，并须用实际样本验证。本地拉片项目只用于比较抽帧、时间定位和报告组织的实现方式。

下文外部研究结果只在各自实验范围内成立。本文提出的状态、接口边界、校准流程均为 Toonflow 产品建议，不能称为行业标准。没有经本项目验证的分值阈值，也不据模型排名直接认定某一条视频合格。

## 3. 公开方案比较

资料均于上述日期核验；论文摘要级核验与官方使用文档核验分别注明。未把下载代码、安装成功或论文相关性视为部署验证。

| 研究或工具 | 核验到的能力 | 对 Toonflow 的价值与限制 |
| --- | --- | --- |
| [VBench 2.0 官方说明](https://github.com/Vchitect/VBench/blob/master/VBench-2.0/README.md) | 人物、可控性、物理等评测；自定义输入仅明确支持人体结构、身份、服装、多样性和多视图一致性 | 可借鉴维度拆分；不能声称任意成片可直接运行全部维度。其多样性评测要求同提示词至少 20 条视频，每镜 4 条属于生产目标，不满足该评测条件 |
| [VBench I2V 官方说明](https://github.com/Vchitect/VBench/blob/master/vbench2_beta_i2v/README.md) | 参考图主体、背景一致性及运镜等自定义视频评测 | 可作参考资产一致性候选。运镜接口列出七类：左右摇、上下摇、推近、拉远、静止；不足以覆盖复杂组合运镜。文档列出的比例选项也不能直接证明竖屏兼容 |
| [T2V-CompBench 官方仓库](https://github.com/KaiyueSun98/T2V-CompBench) | 七类组合关系；分别采用多模态模型、检测及跟踪 | 借鉴“谁做什么、对象关系、运动绑定”的拆解。依赖多个模型，须验证遮挡、接触和动作先后，不能用物体出现代替动作完成 |
| [VideoScore2 官方模型卡](https://huggingface.co/TIGER-Lab/VideoScore2) | 视觉质量、文本遵循、物理常识三个维度；模型卡标注约 8B、BF16、Apache-2.0 | 适合做候选排序基线。官方示例以 2 fps 取视频，不能证明它捕捉到所有短暂错误；没有覆盖中文台词、口型或本项目逐动作验收的保证 |
| [VideoAlign / VideoReward 官方仓库](https://github.com/KlingAIResearch/VideoAlign) | 视觉质量、运动质量和文本遵循奖励模型 | 适合作为另一排序基线；奖励高低不是逐项验收证据，需与人工判断对照 |
| [VideoGen-Eval 论文](https://arxiv.org/abs/2503.23452) | 摘要提出内容结构化、多模态判断及时间密集维度工具 | 支持研究分工评估架构；本轮未核验完整部署与成本，不据摘要选定工程依赖 |
| [MSVBench，ACL Findings 2026](https://aclanthology.org/2026.findings-acl.1203/) | 摘要给出分层剧本、参考图与跨镜混合评估框架 | 提醒验收要覆盖跨镜连续性。论文报告的人类相关性不能转换为 Toonflow 单镜准确率；部署细节待进一步实测 |
| [FilmBench，2026 年 7 月预印本](https://arxiv.org/abs/2607.24241) | 摘要提出电影语言维度、多镜头及参考生成评测 | 用于补足摄影与剪辑层面的研究方向。本轮仅核验论文概述，未验证 FilmOps 代码可用性；不直接采用其分值 |
| [VidHalluc 论文](https://arxiv.org/abs/2412.03735) | 研究视频理解模型的时间相关幻觉 | 评审模型也可能误判；必须保留可回放证据，无法确认时允许弃判 |

这些方案覆盖面互补。优先比较 VideoScore2 与 VideoReward 的排序效果，再按实际错误补充动作、参考图与跨镜检查；暂不整套部署多个基准及其全部依赖。

## 4. 建议的审计内容

以下是产品方案草案，须校准后才能成为自动放行策略。

| 层次 | 检查内容 | 证据与决策方式 |
| --- | --- | --- |
| 文件与技术 | 完整解码、时长、分辨率、显示比例、帧率、必需音轨 | 机器结果可复现。时长按实际工作流帧数约束核对，不能直接用请求秒数与容器秒数完全相等判定 |
| 图像与参考 | 人物、服装、道具、环境；肢体变形、穿模和闪烁 | 保留参考图及相关时间段。遮挡、背面或小人脸可能导致无法确认；不能凭单帧证明全程一致 |
| 动作与运镜 | 动作主体、对象、顺序、接触关系、结束姿态、构图和机位运动 | 分镜要求拆成可观察检查项；从视频建立观察记录，再与要求比较。避免照抄提示词充当观察结果 |
| 语音与声音 | 台词完整性、额外语句、说话人、旁白、截断、声音异常 | 保存音频区间与无诱导转写。可疑差异二次转写或听审；语音识别相同不代表音色、表演和说话人正确 |
| 音画关系 | 可见发声人物的口型与时间偏移，音效事件时机 | 仅在适用条件下评估口型；画外旁白为不适用，口部不可见则需说明证据不足 |
| 跨镜衔接 | 人物与服装、道具位置、动作状态、空间方向和声音衔接 | 联合相邻片段评估；单镜通过不能证明拼接通过 |

[ffprobe](https://ffmpeg.org/ffprobe.html) 支持读取流和容器信息；完整解码应另执行 FFmpeg 解码验证。[FFmpeg 滤镜](https://ffmpeg.org/ffmpeg-filters.html) 可定位黑场、近似冻结、静音等区间，但这些现象可能是创作意图，检测结果应先作为候选问题。冻结不能等同于“动作未完成”，静音不能等同于“应有台词缺失”。

[Whisper 官方模型卡](https://github.com/openai/whisper/blob/main/model-card.md) 明确提示可能输出未实际说出的文字。因此 ASR 仅提供转写证据。台词要求与识别结果都应保存原文；同音字归一化只能辅助比对，不能掩盖真实错词。

[Oxford SyncNet 项目](https://www.robots.ox.ac.uk/~vgg/software/lipsync/) 专门研究音画同步，可列为口型检查候选。采用前仍须验证古装人物、侧脸、低分辨率和遮挡条件；其结果不能替代台词语义检查。

## 5. 状态、证据与产品接入建议

每个检查项建议使用 `pass / fail / unverified / not_applicable`，分别表示通过、不通过、未确认和不适用；错误、超时及工具缺失不能写成通过。不适用需要理由。当前五个布尔值无法完整表达这些状态，未来升级时应保留旧人工记录及其来源，不能伪造旧记录的自动证据。

建议记录：分镜与视频标识、媒体 SHA-256、剧本和提示词版本、参考资产哈希、生成模型/工作流/种子、评估器版本、抽帧时间点、检查要求、观察事实、问题区间、证据路径、结论和人工复核记录。任何输入变化都应标注旧审计与当前版本不一致，保留历史，重新审计。

分镜表、面板和视频轨道应查询同一份审计记录。界面显示可回放的问题区间、要求与观察差异、复核状态及合格数量。相同文件哈希不能重复计数；哈希不同也不能独自证明内容具有足够差异。

初始阶段自动模型只提供建议。人工确认或经过校准的逐项规则才决定合格；必需项未确认时保持待复核。质量分用于排列候选，不能以画面美感高分抵消动作缺失或台词错误。修订建议应定位到 Toonflow 内的分镜或提示词版本，并保留修改前后对照。

不因一次低分自动启动无限重试；如以后开启生成闭环，应明确次数、成本、失败停止条件及用户可见的任务状态。这是产品设计建议，不是研究结论。

## 6. 校准实验建议

1. 从已有实际输出建立样本集，按分镜和生成来源分组，保留好例、坏例及无法确定的例子；训练/调参样本与最终验证样本分离，避免相似片段泄漏。
2. 标注动作漏做、次序颠倒、结束未稳、人物变化、机位错误、台词缺漏、额外语句及口型异常。正常静止、合理静音、遮挡和旁白应纳入反例，检查误拒绝。
3. 人工逐项观看和听审，标记时间区间；重要争议进行独立复核。人工意见不一致的样本保留分歧，不强行设为真值。
4. 对比“技术测量 + 人工”“通用视觉模型分项判断”“VideoScore2 / VideoReward 排序”三个基线。评审条件与生成提示词版本固定，单独测试低密度抽帧和疑点区间加密方案。
5. 分项统计误放行、误拒绝、未确认比例、重复评审一致性、耗时、显存和费用，并给出样本量与不确定性。优先降低关键错误误放行；不能只报告平均相关性或总分。
6. 根据留出样本确定哪些检查可自动裁定；证据不足的维度继续人工复核。具体阈值和放行范围必须由实验形成，不在此预设。

现有试验片可作为待标注材料，但抽帧观察及 ASR 输出本身不构成完整人工真值，也不能据此宣称上述方案已验证有效。

## 7. 实施次序与尚未解决事项

建议先补齐证据保存、技术检测、四态结果与人工复核页面；随后离线比较候选视觉评估器，再接入经验证的动作与声音检查，最后评估跨镜和有限重试闭环。

尚需实测：中文复杂动作和台词表现、竖屏输入处理、参考资产身份误判、时间采样漏检、模型显存和延迟、与视频生成任务的 GPU 资源竞争。VideoScore2 模型卡中的参数量不等于实际运行显存保证。部署前还需逐项核对选定代码、权重及数据的许可证。

若后续下载评估模型，权重实际存放在 `/home/ubuntu/llmspace/LLM-Model/Playtime-AI/models/<作者>/<仓库>/` 并先检查已有文件。文本要求提取可沿用项目默认文本 API；视频观察必须由实际接收图像或视频的评估器完成，纯文本模型不能凭提示词证明成片内容。

首轮调研本身未安装模型、修改运行代码或提交视频。后续原生测试已增加文件技术检测、声音预算预检和试片，并开始下载离线声音理解候选模型；这些后续动作与首轮研究结论分开记录。迄今没有依据技术检测或 ASR 把待验视频自动标为合格。
